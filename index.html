PAPER PLUGIN

It watches. It never shuts the door.

Firmament records which accounts join from which addresses and tells your staff when that looks like one person wearing several names. There is no code path in it that refuses a connection — which is precisely what lets it run on a server that cannot afford to turn away a real player by mistake.

LOOKUP/alts <player>

THE IDEA

Detection, not prevention.

Blocking suspected alts means blocking some number of real players, silently, forever. They cannot appeal to you because they never got in — which is why servers that do it rarely believe they have a problem. Firmament takes the other trade: it never denies anyone, and it makes sure you find out fast.

shared address

Someone else has been here

An arriving account whose address already belongs to a different account raises an alert. That is the whole primary signal, and it costs two lookups in memory.

first join

Never seen before

Every evasion begins with a first join. Broad, and on a busy server noisy — turn it off if it drowns the alerts you actually want.

watch list

Names repeat

People are creatures of habit with usernames. Configured fragments match case-insensitively with the Floodgate prefix stripped, so one entry covers Java and Bedrock alike.

hosting note

A hint, never a verdict

Addresses in configured hosting ranges are annotated on the alert. Nothing is ever done about it. Plenty of ordinary players use a VPN, and some carriers route through space that looks like a datacenter.

Alerts reach in-game staff holding firmament.alerts, the console, and Discord through DiscordSRV if you have it. Discord dispatch happens off the main thread, so a slow API call can never sit in front of a login.

THE VIEW

The link, and the evidence for it, on one row.

A flat list of names answers who else but not how do you know, and the second question is the one you have to answer before acting. The tree puts the account at the top, one row per address beneath it, and the accounts seen on that address along the row.

SHAPEroot → address → the accounts on it
re-root

Click to walk

Clicking any linked account re-roots the tree on it, so you can follow a shared address to the next account and see what it touches. That second hop is where the accounts a one-step lookup misses actually live.

transitive

It closes the set

Two accounts can share nothing directly and still belong to one person, linked through a third. The walk follows accounts to addresses to accounts until nothing new appears.

platform

Java and Bedrock

Java accounts draw as player heads. Bedrock accounts deliberately do not — asking Mojang for a profile behind a Floodgate name starts a lookup that can never succeed.

DAY ONE

Your history already exists.

A watcher that starts from nothing is useless for months — and the alt you want to catch signed up long before you installed anything. Your server has been printing the address on every login since forever, and the rotated logs are still there.

BACKFILL/firmament import

Reads .log and .log.gz alike, off the main thread, and only when you ask — never at startup, because spending seconds of disk unannounced while players are online is rude. Running it twice writes nothing the second time. A file that will not open is skipped and counted rather than aborting the run, so one truncated archive does not cost you the other nine hundred.

OPERATIONS

Four commands, one of them the point.

/alts

The tree

Opens the view for a player. Console gets the same answer as text, since RCON cannot open an inventory.

/firmament import

Backfill

Reads history out of the server’s own logs.

/firmament stats

What it knows

Pairings held, watch fragments loaded, hosting ranges parsed, and whether Floodgate was found.

/firmament reload

Re-read config

Watch list, hosting ranges and alert routing, without a restart.

Permissions: firmament.lookup for /alts, firmament.admin for the rest, firmament.alerts to receive alerts in game. All three expose player IP addresses — treat them as a privacy boundary, not a convenience toggle.

HONESTY

What it cannot tell you.

A household looks like an alt

Two siblings on one connection are indistinguishable from one person with two accounts. Firmament reports the link and says so on every lookup; the judgement is yours and it cannot be automated away.

A new network breaks the chain

Correlation is by address. Someone who changes network between accounts will not link, which is why the name watch list exists alongside it.

It will not stop anyone

By design. If you need people kept out, a whitelist is the honest way to do it, and it is a different feature than this one.

Storage is one tab-separated line per name-and-address pairing, appended, never rewritten — a player joining from home nightly costs one line, not one a night. It is a list of your players and their IP addresses. Keep it off any public repository.
